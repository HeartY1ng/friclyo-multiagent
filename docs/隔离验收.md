# 隔离验收

本页说明当前验收边界；完整命令、费用、依赖和预期结果见 [宿主验收入口](../tests/host/README.md)。宿主每条单独运行、记录退出码和证据，历史提交说明中的通过数量不代替当前版本实测。

## 要验证的边界

两种工人都拒绝数据根内账本、配置、素材、其他轮交付与运行时、宿主控制目录以及敏感凭据路径；本轮交付可读写。OpenCode 仅额外开放本轮私有运行时、临时目录和只读模板/快照，不再开放整个 OpenCode 运行时。

OpenCode 还禁止用户数据区域的内容和扩展属性读取，允许元数据与必要工具精确路径。Codex 采用方案 A：不限制数据根外的一般用户数据读取，保留敏感目录拒绝；原生权限无法只开放元数据，因此不能声称 Codex 实现了 OpenCode 的根外禁读。探针对 Codex 根外用户文档、公共/系统临时文件和其他轮次根外 ASCII 临时文件要求可读，对根内其他轮次仍要求拒绝。写入限定本轮交付、本轮私有状态/临时目录与 `/dev/null`；其他临时目录不允许写。详细目录、保留和手工清理说明见 [运行目录与边界](运行目录与边界.md)。

OpenCode 提供商 key 经宿主读取、匿名管道交给反向代理，工人模板只有假 key、环境没有真 key。工人只连本轮回环 HTTP 端口，宿主代理向固定官方 HTTPS 路由添加 Bearer；不提供 CONNECT。凭据探针核对环境、模板、ps/sysctl、日志、端口限制和清理，不能用守则复述代替这些检查。

## 检查层次

1. `tests/run_all.py` 与 `test_isolation_check.py` 检查替身和判定逻辑，无真实模型费用，不能证明 macOS 内核隔离。
2. `isolation_check.sh --offline-only` 用确定性 Python 探针检查读写与目录列表；另用 `runtime_rounds.py` 查两轮 OpenCode 运行时，`proxy_credentials.py` 查认证和网络边界，`test_proxy_tcp.py` 查代理生命周期。各项用途和预期见宿主入口表。
3. `sandbox_doctor.py` 检查工具兼容性及真实 OpenCode 的中英文路径生产入口对照，使用假上游，不产生模型费用；它会启动临时本地服务。诊断矩阵只改变合成夹具，不能授权生产权限放宽。
4. 完整 `isolation_check.sh` 各调用一次 Codex、DeepSeek 复述守则，需要真实登录/钥匙串并产生用量。`codex_tmp_smoke.py` 另验证真实模型执行工具、Swift 与拷回。`network_check.sh --live` 是真实 OpenCode 网络冒烟入口；默认不加 `--live` 时不调用真实模型。

内核探针预先在沙箱外验证假哨兵确实存在且可读，涵盖账本、配置、偏好、其他轮、素材、指向禁读路径的链接、假敏感目录、根外用户数据和临时目录。写入检查还比较宿主侧前后内容；本轮正向对照要求读写、临时环境和工具启动成功。禁读项只有 EACCES/EPERM 才通过，文件不存在不算；方案 A 的可读项必须读成功。

Codex 使用当前 `codex sandbox` 接口及 `codex_permission()` 命名权限，不使用旧的 `sandbox macos` 写法，也不用 `-s` 覆盖命名权限。内核探针使用假 CODEX_HOME，不读取真实登录内容；真实复述才沿用宿主登录。OpenCode 使用生产入口共用的 `seatbelt()`。父拒绝、子放行、链接目标和继承合并是否生效，应看实际 CLI 与内核结果，不能从规则外观推断。

## 结果与失败处理

无完整 JSON 的探针记“探针未运行”或“探针未完成”，内核项为 `null`，而不是把未启动算作拒绝成功。终端分别汇总通过、未通过、未判定，`summary.json` 保留状态、退出码、原因和日志位置。真实守则复述独立计分，只证明模型收到守则文本，不证明模型命令能力或隔离。

完整隔离检查全部 true 才退出 0；`--offline-only` 预期内核项全 true、两项真实复述 false，因缺复述整体退出 1。这是有意的未完成完整验收，不能写成全套通过。不要固定引用历史的 22、64 或 74 项数量。

轮次公开日志在结束且确认进程组回收后发布，运行中应由宿主查私有控制目录。失败时保留原始规则、CLI 版本、启动器/子命令退出码、stderr 和回执，停止对应动作并报告需要输入；不得删拒绝项、扩大父目录权限或换路径重试。内核未运行、付费项未跑、诊断警告和产物未核对应分别披露。轮次目录默认保留；确认进程组已回收、产物和证据已留存后，可运行 `aw clean [--days N]` 预览已收卡且有可信退出证据的私有目录；`--yes` 仍需输入数据根完整路径。交付目录、账本和不满足安全条件的节点不会由该命令删除。
