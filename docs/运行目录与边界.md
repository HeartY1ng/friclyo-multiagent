# 运行目录与边界

本文说明运行目录及边界约定；路径中的数据根是 `$FRCLYO_HOME`（默认 `~/AgentWork`），轮次名不能为空，只能含 ASCII 字母、数字、`-`、`_`，且不能以 `-` 开头；任务号须符合账本编号格式。执行完成不等于产物验收通过。

## 每轮目录与保留

| 位置 | 用途与工人权限 | 轮结束后 |
| --- | --- | --- |
| `$FRCLYO_HOME/交付/<任务>/<轮>/` | 本轮任务、输入副本、产物、结果与公开回执；本轮可读写，OpenCode 的网络信息与代理拒绝日志另受保护 | 保留，作为验收与追溯材料 |
| `$FRCLYO_HOME/运行时/opencode/rounds/<任务>/<轮>/` | 本轮 `config/data/state/cache/tmp/home`；仅本轮 OpenCode 可读写。实际 XDG config/data/state 指向这里，缓存与临时环境指向下面的纯英文目录 | 保留，不自动回收 |
| `$FRCLYO_HOME/运行时/opencode/worker-<任务>.<轮>.json` | 本轮无真 key 的模板，精确路径只读 | 保留 |
| `$FRCLYO_HOME/运行时/opencode/models.snapshot.json` | 共用模型快照，工人只读；来自宿主本机缓存，不自行下载 | 保留，不按轮删除 |
| `$FRCLYO_HOME/运行时/控制/<codex或opencode>/<任务>/<轮>/` | 宿主捕获、监督状态、可信回执与模型观察；工人禁读禁写 | 保留，故障排查和模型观察仍会用到 |
| OpenCode：`$FRCLYO_HOME/tmp/<任务>/<轮>/` | 本轮临时文件和编译缓存；物理路径含非 ASCII 时回退到 `/private/tmp/frclyo-<uid>-<根哈希>-<任务长度>-<任务>-<轮>` | 保留，不自动清理 |
| Codex：宿主 HOME 下 `.frclyo-work/<根哈希>-<任务长度>-<任务>-<轮>/` | 数据根外的本轮私有 TMPDIR、HOME 与缓存；若父路径非 ASCII 或位于数据根内，回退到 `/private/tmp/frclyo-work-<uid>/…`；仍在根内则拒绝准备 | 保留，不自动清理 |

运行时、模板和临时叶目录独占创建；已有同名节点会失败，不能复用旧轮次覆盖重跑。`TMPDIR/TMP/TEMP`、`TMPPREFIX` 和 Swift/Clang 等缓存变量由入口设置。Codex 的私有 HOME 用于模型执行的命令，宿主登录身份不随之替换。

轮次目录默认保留；确认进程组已回收、产物和证据已留存后，可运行 `aw clean [--days N]` 预览已收卡且有可信退出证据的私有目录；`--yes` 仍需输入数据根完整路径。交付目录、账本和不满足安全条件的节点不会由该命令删除。

## 派活、复现、合并与发布目录

这些是宿主大脑的管理入口，不会扩大工人的目录或凭据权限；任务草稿和输入先准备好，再运行 `aw 派活`。

| 位置 | 用途与边界 | 保留方式 |
|---|---|---|
| `$FRCLYO_HOME/任务卡/<任务>-<轮>.txt` | `aw 卡 新建` 从四种专用模板生成草稿；任务须已开卡，目标占名则拒绝，不登记执行轮次 | 完成范围、输入、验收和预算后再派活 |
| `$FRCLYO_HOME/素材/<任务>/` | 派活默认输入；队列中的 `卡`、`输入` 相对数据根解析，也接受绝对路径；无材料提供空目录 | 完整框架基准放 `框架/`，保留派活时版本 |
| `$FRCLYO_HOME/运行时/派活/<批次号>.jsonl` 及同目录 `.log` | 批次结果及每工人独占 stdout/stderr；同数据根的 OpenCode 提供商锁只协调经 `aw 派活` 启动的批次 | 不自动收卡；试跑不生成运行目录或账本备注 |
| `$FRCLYO_HOME/运行时/复现/<任务>-<轮>/run-<随机标识>/` | 完整测试输出、`results.json`、`run.json`，沙箱模式另存 `sandbox.sb`；每次尝试使用 `<测试文件名>.attempt-N.log`（长名截短加完整 SHA-256） | 保留证据，临时执行副本结束后清理 |
| 合并的开发版目录（`--到`） | `aw 合并` 默认从 `素材/<任务>/框架/` 和 `交付/<任务>/<轮>/交付/框架/` 三方比较；三棵树不可相同或互相包含 | 只写明确目标，既有权限保留；语法失败回滚本批，冲突可能留下其他已应用文件 |
| `$FRCLYO_HOME/框架` | 迁移后为稳定符号链接，指向只读物理版本；工人启动时固定版本 | 发布或回滚原子切换，已启动工人继续旧版 |
| `$FRCLYO_HOME/框架-版本/<完整提交号>/` | 只读快照，禁止手工修改；开发工作仍在 `框架-开发/` | 不自动删除，按下述条件经 `aw clean` 清理 |
| `$FRCLYO_HOME/框架.迁移前` | 首次迁移保留的原稳定仓库，供撤销迁移使用 | 迁移与撤销均须停派活并等已有工人退出 |
| `$FRCLYO_HOME/运行时/发布/`、`运行时/验收/`、`台账/改动台账.md` | 发布事务／指纹、候选验收证据、人工可读记录 | 失败须核对是否已切换，不能只看命令退出码 |

### 复现沙箱与测试契约

`aw 复现 <任务> <轮>` 默认选 `--框架 输入`，测试原轮次 `输入/框架`；`--框架 交付` 选 `交付/框架`，目录路径选指定树。所有选择均先复制到本次临时目录；缺少指定树明确失败，不回退。`FRCLYO_REPRO_ROOT` 及兼容变量由命令设置为所选临时副本，宿主同名变量不能替代 `--框架`。直接运行模板测试时才可自行设置该变量，测试仍须先复制到入口 `$TMPDIR`。

默认使用 macOS `sandbox-exec` 禁网，仅临时副本与 `/dev/null` 可写；沙箱不可用不自动降级。测试需查进程或自己开沙箱时，宿主核查测试后可显式加 `--不套沙箱`（`--no-sandbox`），此时本命令不施加网络／文件沙箱。两种模式均保留复制、干净环境、每项含兼容重试 300 秒总限时和后代收尾。TMPDIR 必须在用户 HOME 与原轮次之外，不合要求不换路径重试；这与工人入口分配私有 TMPDIR 是不同场景。复制跳过 `.git`、`__pycache__`，拒绝其余链接和特殊文件。

测试退出 1 表示复现，0 表示没复现，其他码为测试本身出错；普通 `ERROR`、`FAIL` 和异常文本不覆盖退出码。非零退出伴随匹配的行末 `sandbox_apply: Operation not permitted` 诊断归为“环境受限：沙箱不能嵌套”，不做缺模块兼容重试；超时、启动失败、未确认回收优先报执行错误。修复版须逐项全部没复现且无跳过／环境受限，不能只看命令退出 0。精确选择、兼容变量、诊断匹配、日志长名规则及命令退出码见 [README](../README.md#复现交付测试)。

### 合并与版本清理

`aw 合并` 的 `--试跑` 计算计划并检查语法但不写开发版，`--只许` 只提醒范围外改动而非过滤；`--并集` 可重复，用于已人工核对的 `.py`、`.sh` 或带可识别 Python/Shell shebang 的无扩展名脚本（包括 `bin/aw`）。所有实际写入的这些文件都检查语法；双语言 `bin/aw` 包装分别检查 Shell 启动前缀和 Python 正文。删除须显式 `--允许删除` 且不能覆盖开发版改动；同一开发目录的合并须串行，不支持链接、特殊文件或自动文件／目录互换。命令不改账本、不代表验收。

`aw 发布` 要求开发版 HEAD 干净且已推到对应分支的本地文件远端，先验收候选再切换；失败可能是切换后的看板重启或完成记录失败，须运行 `aw 版本` 核对。初次迁移／撤销停派活，日常发布／回滚可与已有工人并行。付费验收须有相应费用授权。

`aw clean` 同时预览符合条件的轮次私有目录与旧版本，`--yes` 仍须完整数据根路径确认。版本只有在完整登记、支持启动锁、无人使用且不是当前或上一个版本时才可删除；进程信息不全、从旧代码迁移而缺启动锁协议时保留。交付、账本及不满足条件的节点保留。

合并权限以本轮实际 `输入/框架/` 比较；`--基准` 只改内容基准。缺输入先报告需要输入；已有文件保留开发版权限，新增文件沿用交付权限。并集重跑保留已完整包含的连续工人块；结果不变不重写，候选重跑不稳定则报冲突保留开发版，不能全文件去重。详见 [合并说明](../README.md#合并工人成果)。

发布切换后收尾失败保留已验收入口与 pending，修复后用原发布命令补做；显式 `aw 回滚` 优先于未完成发布收尾。快照补登记、候选清理、中断删除与至少一次收尾语义见 [失败恢复](../README.md#失败恢复与版本状态)。

### 批次信息与回执例外文件

`运行时/派活/<批次号>.批次.json` 记录批次号、开始时间、总件数、并行数、额度上限及任务／轮次列表，结束时原子补入结束时间和完成／被中断／校验失败状态。无结束字段不证明进程活着，“完成”不代表逐项成功或验收通过；逐项结果仍在 JSONL。正式校验失败只写批次信息，试跑不创建它。字段与坏输入规则见 [批量派活](../README.md#批量派活)。

`$FRCLYO_HOME/回执例外.jsonl` 位于账本旁，存补登说明，以兼容旧版账本；旧版忽略此文件。收卡时的例外仍存账本备注。例外只豁免回执／交付证据问题，不豁免未收子卡；恢复重新打开后，旧例外不适用于新轮，登记时已有的轮次仍被豁免。专用命令（`完成 --回执例外`、`回执例外`）登记时会记下当时已有的轮次清单，只豁免清单里的轮次；没有清单的旧记录按时间判断，同一秒不豁免。选择优先级与日审规则见 [日审与回执例外](../README.md#日审与回执例外)。

### 版本元数据与工人使用记录

版本元数据仍位于 `运行时/发布/<完整提交号>.json`，原字段继续保留，增加：

| 字段 | 含义 |
|---|---|
| `prepared_at` | 此版本元数据首次成功准备的 UTC ISO 8601 时间，结尾为 `Z` |
| `published_at` | 首次发布/迁移切换的 UTC ISO 8601 时间；准备未切换为 `null`，旧记录可缺失。重发同版本、回滚不覆盖已有值，回滚不为旧记录补造发布时间 |

`published_at` 在切换后的收尾阶段记录，并先保存在 pending 中以便重试沿用。若进程在切换后、时间首次落盘前被杀，恢复时记第一次确认切换完成的时间；无法还原被杀瞬间的精确时刻。旧元数据缺失的历史时间不从目录 mtime 推测。

启动器通过原有 `pin_worker` 获取版本共享锁后，在 `运行时/发布/users/<pid>-<随机标识>.json` 登记：

| 字段 | 含义 |
|---|---|
| `version` / `worker` | 完整提交号、`codex` 或 `opencode` |
| `task` / `round` | 任务号、轮次；无法从合法编号读取时为 `null` |
| `pid` | 启动器 PID；exec 到工人 shell 后保持相同 |
| `started_at` | 登记时间，UTC ISO 8601 |
| `process_started_at` | `LC_ALL=C ps -p <pid> -o lstart=,stat=` 的进程开始时间身份；无法查询时为 `null` |

供看板调用的只读函数为 `frclyo.release.worker_usage(root: pathlib.Path) -> list[dict]`。传入已规范化的数据根。每项返回以上字段及 `active`：`True` 表示 PID 和开始时间匹配，`False` 表示进程已退出/成为僵尸/PID 已被复用，`None` 表示无法确认。函数不创建目录、改写记录、清理陈旧记录或恢复 pending；只读取管理文件和进程开始时间/状态，不读取任务正文或进程环境。结构损坏/无法读取的管理文件抛出异常，调用方应显示未知，不当作空列表或零占用。

`version_rows(root)` 的每行额外提供 `published_at`、`valid`、`rollbackable`、`problem`、`deleting`、`users`（仅确定活跃的使用记录）、`usage_unknown`。旧字段保留，`path` 仍是 Path；序列化时需自行转成字符串。该函数继续进行原有进程路径/cwd 扫描，不是轻量文件列表。工人数结合扫描与已确认活跃登记，避免登记为活跃而计数为零。

看板应按 `active is True` 并与稳定入口提交号比较，展示“谁仍在用旧版本”；`None` 单列未知。旧快照的旧启动器不会新增使用记录，因此空登记列表不能证明旧版本无人使用。清理继续保留原来的进程扫描和共享锁校验，不以记录是否存在作为删除依据。进程开始时间来自系统 ps，分辨率为秒；不能当作高精度进程身份或安全认证。看板的展示口径见 [版本与派活](../README.md#版本与派活)。

## 隔离现状

两种工人都禁止访问数据根中的账本、配置、其他轮交付及宿主控制目录。OpenCode 只开放本轮运行时、纯英文临时目录，以及本轮模板和快照的只读精确路径，不开放整个 `运行时/opencode/`。

OpenCode 还禁止读取 `/Users`、`/Volumes`、`/private/tmp`、`/private/var/folders` 和宿主 HOME 中的用户数据内容与扩展属性，保留本轮路径、精确工具文件等必要例外。文件元数据可读，可能暴露存在性、类型、大小等；这不允许读取内容或列出受保护目录。系统工具树仍可读。

**Codex 不实施上述数据根外用户数据禁读。** 原生命名权限无法只放元数据，当前方案保留根外一般读取范围，同时继续拒绝敏感路径和实际登录、配置路径。代码中的宿主探针也把根外用户文档、公共/系统临时文件、其他轮次根外 ASCII 临时文件列为 Codex 可读对照。因此“其他轮次不可读”指数据根内的交付与运行时，不能扩展为根外临时文件也保密。

交付写入只限本轮；运行所需的本轮私有临时目录、OpenCode 本轮状态目录以及精确 `/dev/null` 是额外写例外。Codex 不允许写其他轮次的临时目录或公共临时根。权限文本不代替当前宿主的内核验证，见 [隔离验收](隔离验收.md)。

## API key 与网络

OpenCode 提供商真 key 由宿主 `keys.get_key()` 读取，经匿名管道交给宿主反向代理，认证只在代理端添加。工人环境不含真 key，模板只有固定占位值；这描述的是 OpenCode 提供商认证链路，Codex 仍使用宿主 CLI 登录。

工人只连接本轮 `127.0.0.1` 随机端口的 HTTP 接口，代理校验证书并经 HTTPS 请求固定本家主机和路径前缀，丢弃客户端认证头，不提供 CONNECT，不跟随重定向到其他主机。其他直连、DNS 和其他回环端口不开放。

| 家名 | 固定上游 | 路径前缀 |
| --- | --- | --- |
| `deepseek` | `api.deepseek.com` | 空 |
| `moonshotai-cn` | `api.moonshot.cn` | `/v1` |
| `xiaomi` | `api.xiaomimimo.com` | `/v1` |
| `zai-coding-plan` | `api.z.ai` | `/api/coding/paas/v4` |
| `zhipuai` | `open.bigmodel.cn` | `/api/paas/v4` |

五家均使用 Bearer 认证；后两家分别是国际编程套餐与智谱国内按量付费，不能互换路由。可用配置 `keychain_entries` 指定已有钥匙串的 service/account，`aw key list` 查看来源而不打印密码。查找顺序为外部条目、默认 `frclyo-<家>` / `frclyo`、显式配置的回退文件；钥匙串只有条目不存在（44）才继续回退，读取失败不会偷换 key。详细配置和删除边界见 [README](../README.md#三步上手)。

## 输入、结果与日志

| 项目 | 上限与行为 |
| --- | --- |
| `WORKER_INPUT_MAX_BYTES` | 默认 `1073741824`（1 GiB），普通文件逻辑大小合计 |
| `WORKER_INPUT_MAX_FILES` | 默认 `10000`，文件与目录条目合计，不含输入根 |
| 输入深度 | 固定最多 128 层 |
| `WORKER_RESULT_MAX_BYTES` | 默认 `16777216`（16 MiB），宿主可调结果上限，必须为正整数且不超过平台读取上限 |
| 工人 stdout/stderr | 合计固定 64 MiB；超出停止工人并报错，保留有界捕获 |
| 宿主后处理日志读取 | 每份按固定 64 MiB 上限安全读取，包括代理 stdout；不是可调结果上限 |

`WORKER_INPUT_DIR` 的根先规范化一次（允许派活方给根路径别名），根内部拒绝符号链接、FIFO、socket、设备等特殊文件，只接受普通文件与目录。先检查整份清单，再复制到隐藏暂存目录，复制时重新核对文件身份，成功才发布为本轮 `输入/`。输入上限必须为正整数；素材检查、复制或限额解析失败会写状态“准备失败”、退出码 2 的回执，不启动工人。输入副本位于本轮可写目录；守则要求按输入材料使用，不等于每个输入文件在内核中只读。

日志先由宿主捕获到控制目录。轮结束且确认进程组已回收后，才向本轮发布 `events.jsonl`、`stderr.log` 和 OpenCode 代理日志；本轮公开日志不是实时流。无法确认回收时，不读工人产物、不更新模型观察，记录失败。结果与回执读取拒绝链接和非普通文件，并限制大小；发布失败的原因保留在私有 `receipt.json`。历史轮次没有可信私有模型观察时，查询返回 `unknown`，不会凭公开结果补造可用性记录。

OpenCode 默认不开详细调试日志；宿主在启动前设置 `OPENCODE_WORKER_DEBUG=1` 才加入 `--print-logs --log-level DEBUG`，仍受输出上限约束。

## 工人使用工具

以注入的 [工人守则](../工人守则.md) 第 3 条和末尾编译、临时文件约定为准：Codex 的 git/构建先在入口提供的 `$TMPDIR` 中建工作子目录，完成后将源码、补丁、可执行文件及日志拷回本轮；Swift/Xcode 的 Codex 构建适用该条，其他情况适用从 `/` 用绝对路径编译的约定。OpenCode 临时文件使用 `mktemp -p "$TMPDIR"`。不要自行改临时、HOME 或缓存环境，也不要在拒绝后换路径重试。
